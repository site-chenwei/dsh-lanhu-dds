# 蓝湖 DDS 代码还原

DDS（转代码）是蓝湖提供的结构化布局树。编译器已将它加工成**自动折叠顶部导航壳层 + 标注底部安全区占位 + 屏内相对坐标 `(0,0)` + 父相位移 + 兄弟间距/`↑nav` + 完整背景渐变与样式 + 切图像素宽高 + 组合小图标预裁资产 + 文案**的单屏紧凑规格表 `screen-N.spec.md` 与单屏裁图 `screen-N.png`。

## 0. 执行铁律（开工一次性拍板 + 默认去顶导重内容与底栏安全区 + 一页一封板）

```
① doctor 检查项目规范与 UI/图标库（读 AGENTS.md + ui-library.md + 主题变量/shared.ts）
   ↓
② screens 列出全部屏 + 快扫各目标页旧源码 <script>/功能块（仅摘路由契约与「旧页有、设计稿未画」的业务开关/警示条，不细读旧 CSS）
   ↓
③ 固定弹 1 次 ask_user_question 一次性拍板三项（严禁跳过、严禁未问先 build、严禁事后补问）：
   1) 整体重构 Rewrite vs 局部优化 Patch
   2) 本次纳入的屏→路由页映射（明确排除未点名路由屏与全局密码键盘屏）
   3) 步骤②扫出的「设计稿未画既有业务开关/提示条」去留（多选项必须原子正交，禁写互斥组合句）
   ↓
④ build 仅编译步骤③已确认纳入的屏号（如 screens:"0,1,3,4,5,6,7,8"，严禁无脑传 "all" 编译无关屏）
   ↓
⑤ 单页上下文隔离闭环（写第 k 页时只准读第 k 页的 spec.md + .png，严禁一口气全读所有屏撑爆上下文）：
   读本页 screen-N.spec.md（含顶部「本屏业务切图」清单）+ read_image 看 screen-N.png (+ variants-diff.md)
   → 默认忽略蓝湖顶部导航栏，仅还原实际内容区并做好底栏安全区域高度适配
   → 按所选模式（重构 write / 优化 edit）落盘本页代码
   → 单点运行本页 prettier + eslint 静态门禁（0 错即封板） → 按需压缩本页中间记录 → 再读下一页 spec.md
   ↓
⑥ 全部目标页过完单点静态检查 + 1 次 doctor 确认无残留 → 立即收尾交付（禁跑全量 taro/vite build）
```

1. **默认忽略顶部导航栏，仅关心实际内容区域和底栏安全区域高度适配（最高优视觉边界）**：
   - **顶部导航栏默认忽略**：蓝湖稿顶部的系统状态栏（`9:41`、信号、电量）与标准顶部导航栏（返回箭头、标题、小程序胶囊，常见 `176px` 高，`spec.md` 已折叠为 `# [顶部导航壳层 默认忽略]`）一律视为宿主壳层，**严禁在页面 DOM 中手写渲染状态栏、返回栏或胶囊**（除非用户明确要求实现自定义沉浸式页内头）；仅提取标题交由宿主导航机制（如 `useNavigationBar('标题')` 或路由配置）承接，首块内容顶距直接取 `spec.md` 标注的 `↑nav:<px>`。
   - **底栏与安全区域高度适配强制执行**：蓝湖稿底部的设备手势条（如 `750×68px` 的 `HomeIndicator` 切图，`spec.md` 已标 `# [底部安全区占位 ... 默认忽略切图]`）**严禁当成图片渲染或写成固定 `68px` 死高块**；只还原吸底栏（Bottom Bar / 抽屉底栏）自身的业务内容高度，并强制叠加底部安全区内边距（复用项目容器 `#bottom` 插槽 + `useFixedBottom` 防遮挡留白 + `XwSafeArea` / `var(--safe-area-bottom)` / `env(safe-area-inset-bottom)`）。**整体重构时即便旧页面漏写了底栏安全区也必须补齐，严禁迁就旧代码缺陷而省掉或回退安全区适配。**
2. **单页上下文隔离与一页一封板（根治全量预读引爆压缩重读）**：
   - **严禁一口气全读**：处理多页任务时，写第 $k$ 页前**只准读取第 $k$ 页对应的 `screen-N.spec.md` 与 `screen-N.png`**；在本页落盘并通过单点 `eslint` 前，**严禁**预读后续页面的 `spec.md`/`.png`/旧源码，**严禁**提前调用 `compress` 压掉当前页刚读入的规格表。
   - **封板不回头**：单页一旦通过静态检查即**封板**，后续阶段**严禁**无故回翻已封板页的 `spec.md` 反复微调。
3. **直接消费 `screen-N.spec.md` 与 `ui-library.md`，严禁自写解析/筛图/搜脚本**：
   - `spec.md` 顶部已汇总**「本屏业务切图」清单**，节点上已标明真实像素尺寸、长图截断、`[空白占位切图，勿渲染]`、`[弹层底层页面预览背景，勿当弹层内容渲染]`、线性渐变与组合图标预裁图。**严禁**写脚本扫 `manifest.json` 筛图，**严禁**手翻 `.html`、手跑 `curl`/`Invoke-WebRequest` 拉图或 `System.Drawing`/Python 量尺寸。
   - **本插件无额外校验/压图脚本**：不存在 `check_baseline`、`check_refs`、`crosscheck` 等脚本，也无需用 `sharp`/`pngquant` 压图，**严禁**去插件目录搜不存在的脚本或探测压图依赖。
   - `ui-library.md` 已提取组件专属 props、`v-model`、插槽 `#slot`、`var(--<prefix>-*)` 变量、BEM 子类名 `.xxx__*` 与全量图标名，**严禁**反复进 `node_modules` 翻编译后 `.js` 猜内部 DOM。
4. **工具调用红线**：查看 `screen-N.png` 与切图必须用 `read_image`（**严禁**用文本 `read` 读取 `.png` 二进制文件）；执行过 `prettier --write` / `eslint --fix` 等会改写文件的命令后，再次对该文件调 `edit` 前**必须先重新 `read` 对应片段**；终端命令严格使用当前会话已注入的 shell 工具（如 Windows 会话用 `pwsh`/`win_bash`，勿盲调未注册的 `bash`）。

## 1. 准备：Cookie 固定存一处

Cookie 唯一存放路径：**`~/.dsh-lanhu-dds/cookie`**（可用 `DSH_LANHU_DDS_HOME` 改根目录，权限 0600）。不读环境变量、不读 `.env`、不读配置。

1. **文件存在 → 自动复用**，无需询问用户。
2. **文件不存在 → 工具返回 `missing-cookie`**：把返回里的 `say` + `howToGet` 转述给用户（可用 `ask_user_question`）并停下等待。不要伪造、不要盲写页面。
3. **用户贴回 Cookie → 先验证再落盘**：传给 `lanhu_dds_screens` 或 `lanhu_dds_build` 的 `cookie` 参数，工具真读一次设计图验证通过后自动写入 `~/.dsh-lanhu-dds/cookie`；若返回 `cookie-expired` 则提示用户更换有效 Cookie，工具不落盘坏值。

获取方式：浏览器登录蓝湖 → F12 → Network → 任一 `lanhuapp.com` 请求 → 复制完整 `Cookie` 请求头。
**安全红线**：严禁把 Cookie 写进业务代码、提交仓库或在回复正文回显明文。清除旧值用 `lanhu_dds_doctor({ forget: true })`。

## 2. 查项目规范与 UI/图标库（先跑 doctor）

> 本技能随 `dsh-lanhu-dds` 插件提供，全程调 `lanhu_dds_doctor` / `lanhu_dds_screens` / `lanhu_dds_build` 三个工具（`lanhu_dds_doctor` 自动定位当前会话工作目录，无需手传 `project`）。

1. 调 `lanhu_dds_doctor({})`，一次性拿到：
   - **输出单位 `unit`**：自动读取 `config` 的 `designWidth`（750 → `design`；375 → `css`）或 `postcss` 的 `rootValue`/`viewportWidth`。
   - **项目主规范来源**：
     - 若项目根已有完备的 **`AGENTS.md` / `CLAUDE.md`**，`doctor` 直接认它为最高准则（`rules.delegatedTo: "AGENTS.md"`），**不要**再跑 `init` 生成空白 `project-rules.md`。
     - 若项目既无 `AGENTS.md` 也无 `.agents/skills/lanhu-dds-codegen/project-rules.md`，才跑 `lanhu_dds_doctor({ init: true, ui: true })` 生成模板并结合仓库现状补齐。
   - **内网 UI 组件库与图标库（`uiPackages` / `iconPackages`）**：
     - 若 `ui.present === false`，调 `lanhu_dds_doctor({ ui: true })` 自动扫描内网 UI 组件包（精确解析每个组件专属 `.d.ts` 的 props、`v-model` 绑定、插槽 `#slot` 与包内 `--<prefix>-*` CSS 变量）和图标包（多行折行输出全量单图标名），生成 `.agents/skills/lanhu-dds-codegen/ui-library.md`。
     - **直接查 `ui-library.md` 选用组件、插槽、`v-model`、CSS 变量与图标名**，无需反复进 `node_modules` 跑脚本搜 `.d.ts` 或 `style.css`；仅当极个别复杂组件的深层行为未在表中体现时，才按表中「依据」路径定点 `read` 一次。
     - 若扫描后 `ui.usable === false`，按 `ui.askUser` 向用户索取组件清单或用法示例，**严禁盲猜组件名与 props**。
2. 开工前读一遍项目主规范（`AGENTS.md` 或 `project-rules.md`）、`ui-library.md`、全局主题变量（如 `src/styles/theme.css`）及当前业务模块共享入口（如 `shared.ts`、路由定义）。**禁止**把模板文件里的占位示例抄进业务代码。

## 3. 选屏、契约快扫与开工一次性拍板（每次必问）

### 3.1 选屏与旧页独有功能快扫

1. 调 `lanhu_dds_screens({ url })`，查看每屏 `index / width×height / nodes / raster / title / texts`（`raster: true` 代表整张位图无图层结构，需明确告知用户无法由 DDS 结构化还原）。
2. 用 `glob` 定位目标业务目录下的页面文件，并**快速扫一眼目标页面旧文件的 `<script>` 与功能块概览**（此时不细读旧 CSS，只做一件事：识别原页面是否存在**蓝湖设计稿未画出的业务开关、额外表单项或合规警示条**，以便在下一步一次性找用户拍板，杜绝写到最后才补问返工）。

### 3.2 开工契约确认（全场唯一 1 次提问，先拍板后编译，选项必须正交无歧义）

**无论用户提示词中是否已经写了「重构」或「优化」**，拿到屏清单与旧页差异项后、**调 `lanhu_dds_build` 编译之前**，**固定调用 1 次 `ask_user_question`** 一次性拍板以下全部事项（把预判推荐项放在第 1 个并标 `(Recommended)`）：

1. **任务类型（整体重构 vs 局部优化，单选 `multi_select: false`）**：
   - **整体重构（Rewrite）**：推翻目标页面的旧 DOM 结构与旧 CSS，以蓝湖设计稿实际内容区为唯一视觉基准整文件重写；只保留路由/接口/Store 业务契约与经确认保留的业务功能。
   - **局部优化（Patch）**：保留目标页面既有 DOM 骨架与样式体系，仅针对设计稿变更区块做定点修改。
2. **本次纳入的「屏序号 → 页面文件」范围映射（标题页数必须与明细严格一致）**：
   - 明确分列「**本次纳入改动的 `screen-N → 页面路径`**」（含合在同一页实现的状态/弹层变体屏）与「**画布中排除不改的屏**」（如用户未点名的独立路由屏、跨模块全局公共密码键盘屏）；
   - **严禁**在写着「全部 N 个页面」的选项描述里偷偷塞入第 N+1 个未点名路由页，防止确认后自相矛盾；若想询问是否顺带纳入画布中多出的独立路由页，必须单独设为一个额外可选项。
   - **涉及 `src/components/` 等跨模块全局公共组件的屏**（如全站共用的交易密码弹窗、安全键盘）：默认**只保留调用、不改全局公共组件源码、也不传入 `build` 重复编译**；确需修改时必须单列征得同意。
3. **设计稿未画出的旧页面业务功能去留（若步骤 3.1 扫出则同轮必问）**：
   - 若设为多选（`multi_select: true`），**每个选项必须是彼此独立的原子保留项**（例如拆为「保留顶部退换货警示条」「保留积存金兑换抵扣开关」两个独立勾选项；全不选即全部按设计稿移除），**严禁在 `multi_select: true` 下写出「保留 A+B」「只保留 A」「全部移除」这类互斥组合句**，防止用户多选后语义冲突。
   - **严禁不问就擅自删掉落盘、等写完几十步后再补问返工！**（纯演示假文案如信贷示例协议名直接保留原业务真实协议名即可，无需打扰用户。）

### 3.3 按需编译与产物消费优先级

用户确认拍板后，一次性调 `lanhu_dds_build({ url, screens: "0,1,3,4,5,6,7,8" })` **仅编译本次纳入改动的屏号**（**严禁**未拍板就提前传 `screens: "all"` 把不改的独立页和全局键盘屏全编出来；同一会话内若后续补编某几屏，工具会**非破坏性增量合并**，不会删掉同目录已生成的其他屏与 `reference.png`）。产物位于 `~/.dsh-lanhu-dds/sessions/<会话>/`，**严禁拷入项目目录**：

| 优先级 | 文件 | 作用与正确读法 |
|---|---|---|
| **1（主输入）** | **`screen-N.spec.md`** | **单屏紧凑规格表（几 KB）**：含组件候选、缩进层级、屏内 `(0,0)` 坐标 `@(x,y w×h)`、父偏移 `rel(dx,dy)`/`=parent`、前兄弟间距 `↑gap`/`←gap`、flex 布局、颜色/字号/行高/圆角/边框/阴影、本地切图路径与真实像素尺寸 `(pxW×pxHpx)`、组合碎片图标预裁图 `composite-icon:...` 与文案。**写某屏前直接 `read` 它，无需读 `ir.json`。** |
| **1（主输入）** | **`screen-N.png`** | 该屏设计稿裁图（视觉唯一真相）：核对整体视觉、图标语义、`c:MISSING` 文本真实颜色与层次细节。 |
| **2（多屏必读）** | **`variants-diff.md`** | 自动配对「同页面的不同状态/弹层变体」（如详情页 ↔ 规格弹窗、无地址 ↔ 有地址），直接列出差异块。 |
| **2（总览）** | **`report.md` / `tokens.css`** | 全部已编译屏的汇总体检报告、切图落盘统计与高频色值/字体候选。 |
| **资源** | **`assets/` + `manifest.json`** | 已本地化的切图（含像素宽高）与编译器预裁的 `composite-sN-box-M.png`；业务所需图片语义化重命名后拷入项目静态资源目录，**严禁在代码里直接引用蓝湖线上 URL**。 |

### 3.4 内网切图域名替换规则（`lanhu-oss-*` → `alipic.lanhuapp.com`）

内网通常放行 `lanhuapp.com`、`dds.lanhuapp.com` 与 `alipic.lanhuapp.com`，拦截 `lanhu-oss-*.lanhuapp.com`（TLS `SEC_E_WRONG_PRINCIPAL` 或 HTTP 403）。

- **编译器已内置三级自动回退**：① 直连 `lanhu-oss-*`（单域失败立即熔断）→ ② **自动替换为 `https://alipic.lanhuapp.com/<同名路径>` 并带蓝湖 `Cookie` + `Referer: https://lanhuapp.com/` 拉取逐字节一致的真切图** → ③ 无文字遮挡时从 `reference.png` 裁切兜底，有文字叠加则剥除死链标 `img:PLACEHOLDER(...)`（直接用 CSS 渐变/底色实现）。
- **禁止排障死循环**：切勿跑 `curl` / `Invoke-WebRequest` / `rejectUnauthorized: false` 探测 `lanhu-oss-*`；如确需手工补拉，只用 `https://alipic.lanhuapp.com/<文件路径>` + `~/.dsh-lanhu-dds/cookie` + `Referer: https://lanhuapp.com/`。

**项目写入边界**：

| 应写入项目（正常接入件与交付物） | 严禁写入项目（中间污染） |
|---|---|
| 业务页面/子组件源码、拷入项目静态目录的正式图片 | `design/dds/`、`.lanhu-dds/`、`screen-*.json`、`screen-*.spec.md` |
| `.agents/skills/lanhu-dds-codegen/ui-library.md`（及无 `AGENTS.md` 时的 `project-rules.md`） | `.agents/tmp/`、`dump-ir.*`、`rects-rel.*`、`crop.ps1` 等任何临时文件（确需临时文件只放 `build` 返回的 `tmpDir`） |

## 4. 「整体重构」vs「局部优化」执行硬边界（防死磕旧代码铁律）

确认任务模式后，严格按对应列执行，**严禁混用**：

| 维度 | 整体重构（Rewrite） | 局部优化（Patch） |
|---|---|---|
| **写文件方式** | **一律用 `write` 整文件重写页面模板与样式**。严禁在几十 KB 旧文件上连打一二十次 `edit` 局部缝补。 | **用 `edit` 定点修改目标区块与对应样式**，严禁重写无关区块。 |
| **旧页面源码怎么用** | **只读 1 遍提取「业务契约五件套」后立即脱离旧 DOM/旧 CSS**：① 路由入参与跳转调用；② Store / 接口取数与字段名、格式化函数；③ 页面级导航栏/生命周期 Hook；④ 提交校验与弹层状态联动；⑤ 公共组件调用点。**旧 `<template>` 层级、旧 class 名、旧纯视觉子组件全部丢弃，严禁逐节点比对旧代码！** | 以旧页面 DOM 结构、class 命名与组件拆分为基准，仅对齐 `spec.md` 中变更节点的尺寸、颜色与文案。 |
| **设计稿未画出的旧业务元素**（如旧功能开关、合规提示条） | 按 **§3.2 开工契约已拍板的结论**一次性保留或移除，**严禁在代码里先删后加反复摇摆**（纯演示假文案如借贷示例协议名直接沿用当前业务真实协议名）。 | 默认保留既有页面上的其他业务开关与合规提示，仅改动用户指定的优化点。 |

## 5. 出码规范

### 5.1 冲突裁决优先级

1. **项目既有规范（`AGENTS.md` / `project-rules.md` / 同模块 `shared.ts`）** 决定技术栈、组件引入路径、路由方式、主题变量名。
2. **`screen-N.png`（设计稿裁图）** 决定视觉真值：`spec.md` 标 `c:MISSING(看裁图)` 的文字颜色、图标长相与层次细节一律看裁图。
3. **`screen-N.spec.md` 的几何与样式数值** 决定尺寸、间距、`linear-gradient`、`boxShadow`、圆角（默认 `unit=design` 即 750 设计稿 px，直接写进样式交给构建期 `pxtransform` / `postcss-px-to-rem` 换算，**不要手动除以 2**）。

### 5.2 页面壳层边界：默认忽略顶部导航栏 + 仅关心实际内容区与底栏安全区适配

1. **默认忽略蓝湖 UI 顶部状态栏与顶部导航栏**：
   - 设计稿顶部的手机状态栏（`9:41`、信号、WiFi、电池）与标准顶部导航栏（返回箭头、页面标题、右上角小程序胶囊按钮，750 稿下常占 `y: 0..176px`，`spec.md` 已折叠为 `# [顶部导航壳层 默认忽略]`）属于宿主容器提供的系统壳层：**默认一律忽略，严禁在页面模板里手写状态栏、返回栏或胶囊按钮**（仅当用户明确点名要做自定义沉浸式/渐变透明页内头时才按要求实现）。
   - 页面标题直接通过项目既有宿主导航方式设置（如 `useNavigationBar('标题')` 或路由配置 `navigationBarTitleText`）。
   - 页面 DOM 直接从导航栏下方的**首个实际业务内容节点**写起，其顶部间距直接采用 `spec.md` 标注的 `↑nav:<px>`（即 `首块.y - 顶部导航底边.y`），不要再手算画布绝对 `y` 坐标差。
2. **仅关心实际内容区域与底栏（Bottom Bar）的安全区域高度适配**：
   - **禁止渲染底部手势条切图**：设计稿底部的 iOS Home Indicator 横条（750 稿下常为 `750×68px` 的切图或留白，`spec.md` 已标为 `# [底部安全区占位 ... 默认忽略切图]`）只是安全区高度示意，**严禁将该切图拷入项目，也严禁写成固定 `68px` 死高的占位元素**。
   - **吸底操作栏 / 底部弹窗底栏适配**：仅还原底栏自身的业务高度与内边距（如详情页按钮栏 `120px`、确认页协议栏 `112px` + 支付栏 `120px`），并**统一做好底部安全区域高度适配**：
     - 优先放入项目页面容器标准底栏插槽（如 `XwPageContainer` 的 `#bottom` 插槽），配合项目防遮挡 Hook（如 `useFixedBottom`）为滚动内容区动态留出底部内边距；
     - 吸底容器与底部抽屉页脚统一叠加项目标准安全区内边距（如 `XwSafeArea`、`padding-bottom: calc(<设计内边距> + env(safe-area-inset-bottom))` 或项目全局变量 `var(--safe-area-bottom)`）；
     - **强制补齐，不迁就旧缺陷**：整体重构模式下，即便旧页面漏写了底栏安全区适配，重构后也必须补齐一致的底部安全区高度适配，**严禁以「旧代码没加安全区」为由省掉或回退底栏安全区**。
   - **无吸底栏页面**：在页面滚动容器底部保留常规留白并叠加 `env(safe-area-inset-bottom)`，防止末行内容贴底裁切。
   - **画布截断详情长图**：`spec.md` 标有 `[完整长图被画布底边截断，按真实图片比例自然撑开]` 的图片节点，用 `width: 100%; height: auto; display: block` 完整展示真实长图，不要写死画布截断框高度。

### 5.3 组件复用与流式布局

- **内网 UI 库优先，不手搓已有组件**：先查 `ui-library.md`（含 props、`v-model`、插槽与 `--<prefix>-*` CSS 变量）与模块 `shared.ts`。卡片、按钮、标签、单元格、底部动作面板、步进器、搜索栏、空态优先用现成组件；默认样式与设计稿差 2–4px 属组件库正常刻度，用组件 props、CSS 变量或局部 `:deep()` 微调，禁止全局 `!important` 或改 `node_modules`。
- **同构重复块必抽子组件或 `v-for`**：`spec.md` 顶部「组件候选」列出的同父同宽重复块不复制粘贴 N 份模板。
- **同路由多状态合页**：`variants-diff.md` 配对的状态屏（详情页 + 规格弹层、无地址 + 有地址）合在同一页面组件体系内用响应式状态切换，完整保留原接口调用与路由交互。
- **语义流式布局**：按 `spec.md` 的 `col`/`row`、`pad:`、`↑nav`/`↑gap`/`←gap` 用 Flex/Grid 写文档流；`=parent` 代表与父同框的包装层，合并冗余嵌套；**禁止**照搬 `screen-N.html` 的全屏 `position: absolute`。

### 5.4 图标与组合碎片图标处理（零手工裁图）

1. **优先换项目图标库**：结合 `spec.md` 标注的邻近语义提示 `near:"..."` 与 `screen-N.png` 视觉形态，直接从 `ui-library.md` 的「全部可用单图标名」多行列表中选语义匹配的图标组件。
2. **定制图标 / 组合碎片图标**：
   - 若 Figma 中一个小图标由「CSS 边框节点 + 半截切图」拼成，编译器已自动从整张原图预裁出完整图标写入 `assets/composite-sN-box-M.png` 并在 `spec.md` 标注 `composite-icon:...`——若图标库无替代项，直接拷入该预裁文件或 `assets/` 中的完整切图即可。
   - 若仍无合适切图，写带精确宽高的语义占位块（保留 `aria-label` 或 `aria-hidden="true"`，不留 404 链接）并在交付说明列出待办。
   - **红线**：**严禁**为了一个小图标手写 PowerShell `System.Drawing` / Python / Canvas 脚本去裁切或缩放 `reference.png`。

## 6. 分级验收、完工即停与交付清单

### 6.1 默认必过门禁（静态校验，过检即封板）

内网 H5 项目常依赖网关代理、登录态或商户配置才能在浏览器打开路由。**默认采用静态门禁，禁止因本地起不来服务而卡住，更禁止过检后无限循环自检**：

1. **单点静态检查（禁跑全量构建）**：仅对**本次修改的目标文件**运行项目规定的快速静态检查（如 `npx prettier --write <变更文件>`、`npx eslint --fix --max-warnings=0 <变更文件>`；项目声明无测试框架时不跑 `npm test`）。**除非用户明确要求验证打包产物，否则严禁跑耗时数分钟的全量 `taro build` / `vite build` / `webpack` 生产构建！**
2. **契约与污染自检**：确认 ① 顶部导航已交宿主、实际内容区与底栏安全区高度已适配，核心文案、价格色值与渐变圆角已还原；② 原页面路由参数、Store/接口绑定与拍板保留的业务开关未丢失；③ 全部页面写完后跑 **1 次** `lanhu_dds_doctor({})` 确认 `strays` 为空。
3. **完工即停硬闸与 Git 暂存边界（防收尾空转）**：
   - 全部目标页面单点静态检查 0 报错且 `strays` 为空后，**立即收尾交付**，严禁跨页回翻已封板页面的 `spec.md` 或组件库源码反复微调。
   - **纯视图层还原免立架构决策笔记**：照蓝湖设计稿重写/优化页面模板与样式（未改动跨模块架构、后端接口契约或持久化格式）属于确定性 UI 视图落地，**默认不新建 `.agents/notes/` 决策笔记**（除非用户明确要求；若用户要求撰写文档，严禁在旧源码已压缩后凭记忆编造旧实现细节）。
   - **Git 暂存边界**：若按工作区规范执行本地原子 commit，**只暂存本次改动的业务源码与拷入项目静态目录的业务图片**；此前未纳入版本控制的 `.agents/skills/lanhu-dds-codegen/ui-library.md` 保持 untracked 即可，无需纠结或混入业务 UI 提交。

### 6.2 浏览器 DOM 几何校验（仅当页面已在本地可访问或用户明确要求时）
