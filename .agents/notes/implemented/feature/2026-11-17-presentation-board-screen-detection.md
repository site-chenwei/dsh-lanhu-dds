# Agent Note: 展示板不是屏——选屏加「内容铺满 / 状态栏时钟」两条事实

Status: implemented

## Problem

0.9.1 在两个同一设计稿的真实会话里（36 步 / 19.4 分，43 步 / 18.8 分）都能跑通，`build` 不再崩，`closeout` 之后各只再走 1 步。但两个会话都把一张**展示板**当成了手机屏：

1. **屏是画布，不是手机**。`screens` 返回 `width 1404, height 2588`，规格表首行是 `# Screen 0 — 支付结果 (750×1382, unit=design, 51 节点)`。真实的手机是树里的 `box-3 @(175,324 401×868)`。展示板的结构是「灰底 `rgba(233,236,241,1)` + 蓝色标题牌 + 一台居中手机 + 底部图注」。
2. **画布注释混进了布局树与文案清单**。规格表里 `box-1 @(175,99 278×118) ... "支付结果"` 是设计标题牌，`text-50 @(292,1208 166×27) "支付订单-支付成功"` 是图注；`screens.json` 的 21 条 `texts` 里这两条也在。
3. **壳层折叠失效，规格表却仍然声称折叠了**。状态栏（`9:41`）与导航栏（`支付订单`）都原样展开，而 [spec.mjs](../../../lib/spec.mjs) 那句「顶部状态栏/导航栏已自动折叠」是无条件输出的。
4. **0.9.1 的 ÷1.872 归一在这张稿上是错的**。上一轮按「画布 1404 宽 = 750 基准的 1.872 倍」做归一，前提是屏节点就是设计本体。实际是展示板里嵌了一台 750 宽的手机，画布 px 正好等于设计 px，`div` 应该是 1。归一后全部数值变成真实值的 0.535，而规格表还写着「与切图像素同一空间」——清单里 `assets/330509e209.png — 750×68px` 摆在 `@(175,1155 401×36)` 的槽里，两套空间并不一致。
5. **模型把这一步算术替插件做了**。s5 最终写的 CSS 是 `.ok-icon { width: 108px }`、`.ok-title { font-size: 40px }`、`.ok-desc { font-size: 28px }`，对应规格表的 `58×58`、`fs:21.37px`、`fs:14.96px`，各乘 1.872。`1.872` 在两个会话的推理里出现 493 / 471 次，`401` 出现 421 / 468 次；s5 的 S023（33873 字符）、S026（30536）、S025（25656）、S020（22780）都在反推真实几何。
6. **`scale` 参数静默失效**。s5 在 S010 传 `scale: 1` 想把归一转掉，返回的规格表逐字节相同，模型的推理里写「The spec still uses ÷1.872」。`design` 模式的 `div` 不看 `scale`，但参数描述仍是「强制缩放比（1/2/3）」。
7. **图标名还是去翻 `node_modules`**。两个会话最终都写了 `XwIcon name="CheckOutline"`，找这个名字花了 s5 五步、s6 两步。`ui-library.md` 里已经有全部 151 个图标名，但规格表只写了「不翻图标库找相似的」，没写「需要一个名字时去哪里查」。

## Decision

1. **选屏加两道「像不像一台手机」的判据**（`lib/dds-tree.mjs`）：候选必须有内容铺满自身宽度（最宽的直接子节点 / 自身宽 ≥ 0.85），或顶部 8% 的纵向区间里有状态栏时钟（`\d{1,2}:\d{2}`）。展示板上这两条都不成立——最宽的直接子节点就是那台手机（750/1404 = 0.53），时钟跟着手机下沉到 23% 处。过滤后一个候选都不剩时**回退到原规则**（最浅一层 + 宽度众数），保证判据认不出的设计稿仍按老办法出结果。
2. **壳层说明只描述实际发生的事**（`lib/spec.mjs`）：折叠了顶栏才写「导航栏（标题「…」）已自动折叠」，没折叠就写「本屏没有识别到状态栏/导航栏块，顶栏按项目既有页面的做法处理」；底部安全区同理，没有就不出现那一句。
3. **`scale` 在 `design` 模式下被忽略时给出 warning**（`lib/build.mjs`）：返回体顶层 `warnings: ['scale 只在 unit: css 时生效；…本次忽略 scale']`。顺带把每屏的 `warnings`（编译告警条数）改名为 `warningCount`，避免与顶层同名字段混淆。
4. **规格表图标一节补一句指路**（`lib/spec.mjs`）：`ui-library.md` 已存在时，写明「需要一个图标名时读它，一次 `read` 就有全部名字，不要为此翻 `node_modules`」。是否输出由 `index.js` 检查 `.agents/skills/lanhu-dds-codegen/ui-library.md` 是否存在后传入（`buildDesign({ uiDoc })`）。
5. **扫描结果的 `withProps` 改名 `withSignature`**（`lib/ui-library.mjs`）：它与 `doctor` 里 `ui.withProps`（清单里非「未解析到」的行数）不是同一个数（65 vs 79），同名会让人以为数字对不上。

## Alternatives considered

### 直接丢掉深度 0 的候选

最简单。但「根节点就是手机」的稿子会失去唯一候选，退回 `fallback` 分支；而 0.9.1 的夹具（1404 宽画布、内容铺满、无外壳）会从「归一到 750」变成「不归一」，把一个正确行为改坏。

### 用「内嵌候选更窄且占 55% 高」判定画布

能修这一例。但手机里放一张又窄又高的卡（`600×1000` 于 `750×1625`）也满足，会把卡顶替成屏——修好一个坏掉一个。判据必须来自「这块区域像不像设备的成像面」，而不是父子尺寸关系。

### 用长宽比上限排除画布

这张画布 2588/1404 = 1.84，比手机还像手机，排除不掉；而长滚动页（750×4000）会被误杀。

### 用背景色区分画布与手机

灰底画布 vs 白底手机看起来好认。设计稿里两者经常同色，颜色不是结构事实。

### 让归一去跟随 `scale`

`scale` 本身是猜的（1404/375 = 3.74 取 4），用它当除数会把误差放大。归一只能来自「屏宽 / 项目 designWidth」，前提是屏节点必须是手机。

### 把 `scale` 参数删掉

它是 `unit: css` 项目唯一的手动入口（375 逻辑宽时 `div = scale`）。删掉会让这类项目失去一处覆盖手段，改成警告更小。

## Consequences

- **收益**：展示板稿的屏宽、原点、`div` 一次性对齐——`div = 750/750 = 1`，规格表数值可直接写进代码，不再需要模型换算；画布注释不再进树与 `texts`；状态栏与导航栏重新被折叠，`navTitle` 取自导航栏子树；壳层描述不再与事实相反；`scale` 无效时模型能立刻看到原因；需要图标名时有一步可达的答案。
- **代价**：
  - `meta.scale` 从 4 变成 2（750/375），旧产物目录因此判定不可复用，会重建一次 DDS 与切图缓存。
  - 每屏的 `warnings`（数字）改名 `warningCount`；扫描结果的 `withProps` 改名 `withSignature`。
  - 选屏多是一次 `contentFill` 的 O(子节点) 计算，`hasStatusClock` 只在 fill 不足时才对子树做一次遍历。
  - 规格表首行与树根名从 `screen` 变成手机节点的名字（`box-0`），纯展示差异。
- **验证**（`/tmp/lanhu-golden/verify-092.mjs`，合成 DDS + mock `fetch`）：
  - 展示板（1404×2588 灰底 + 标题牌 + 750×1625 手机 @(327,606) + 图注）：选到手机，`raw.w = 750`、`raw.x = 327`、`scale = 2`。
  - 端到端 build：规格表首行 `# Screen 0 — 支付订单 (750×1625, unit=design, …)`；不含「坐标归一」；不含 `支付订单-支付成功` 与标题牌文案；含「导航栏（标题「支付订单」）已自动折叠」；树里没有 `9:41`；`↑nav` 存在；`screens.json` 的 `texts` 不含两条注释；未生成 `ui-library.md` 时不出现指路句。
  - `scale: 1` 与 `design` 同传：返回 `warnings` 含「scale 只在 unit: css 时生效」。
  - 回归：9382×3254 横排 10 台手机仍是 10 屏；根节点就是手机仍是 1 屏；手机里放 `600×1000` 的窄高卡不会被顶替；`/tmp/lanhu-golden/verify-091.mjs`（单屏崩溃守卫、`design` 归一、图标占位、错误提示分类、`diagnoseProject`）仍全绿。
- **未验证**：
  - 没有在真实设计稿与真实模型上重跑。重跑时的判断数字：规格表首行是手机尺寸而不是画布尺寸；不含「坐标归一」；`texts` 不含画布注释；图标相关步骤 ≤1（本次 5 / 2）；总步数 ≤30（本次 36 / 43）。
  - 展示板里那台手机的真实层级（深度 1 还是 2）是从规格表 `box-3` 的偏移反推的，两次会话都没留下 `dds.raw.json`。
  - 两种形态仍会走回退分支：一台画布上纵向堆两台手机（最宽子节点等于画布宽、无嵌套手机，回退后仍认画布），以及画布内容真的铺满宽度又有顶层时钟的稿子（会被当成屏，此时 `div` 按 `designWidth` 归一，与 0.9.1 行为一致）。
