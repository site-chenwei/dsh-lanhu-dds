# Agent Note: 真实链接回归——顶栏被分组藏进卡片、空屏与「只有标题不同」的屏对

Status: implemented

## Problem

0.9.2 用五个真实蓝湖链接（购买结果、发票管理、地址管理、我的订单、首页/列表/详情/确认）跑完整流程，五张图都编译成功，展示板判据在 1404×2588 的展示稿上按预期选到里面那台 750 宽的手机。剩下的问题全部出在「规格表说得不够实」这一类，其中两条会让模型直接写错代码：

1. **顶栏整块漏折叠**。`我的订单` 屏 1–4 的导航栏在 DDS 里被 Figma 分组塞进了卡片框 `box-4 → box-43` 内部，视觉上仍在屏顶、`@(0,0 750×176)`。`detectScreenChrome` 只遍历根节点的直接子节点，于是状态栏的 `9:41`、「订单详情」、右侧胶囊被当成页面内容写进布局树，模型照着写会在页面里再画一条顶栏。
2. **plan 漏屏没有任何提示**。`地址管理` 那张图有 8 屏，`plan` 只覆盖 7 屏，屏 5（空弹层，2 个节点）被静默丢掉。用户和模型都无从知道少了一屏。
3. **结构完全一致的屏对被写成一节空表**。`地址管理` 屏 0 与屏 7 的树与文案 100% 相同，只有导航标题不同（收货地址 / 地址管理）。`variants-diff.md` 照常输出一节「仅在 Screen 0：（无独有子树）／仅在 Screen 7：（无独有子树）」，模型读不出结论，只能回去读两份规格表。
4. **大段 `↑gap` 会被写成固定 `margin`**。真实数据里 `↑gap` 的中位数 24、p90 38，而 `≥240` 的 12 处全是固定高度稿里的摆放（909、893、787、746…）。规格表只给数字，模型按 `margin-top: 909px` 写，换设备就崩。
5. **`report.md` 的画布行算错**。原文写「画布 9382×3254 设计像素，…逻辑宽 4691」——用画布宽除以 scale 得到 4691 这个没有意义的数；一张画布常横排 5~10 屏，画布宽不是屏宽。
6. **多张画布的 `closeout` 互相覆盖**。一个会话里连着编译 5 张图时，`plan.json` 只留最后一张，收尾清单也就只剩最后一张，前四张的页面文件与去留项等于没拍板过。
7. **空框会被写进 plan**。`screens` 返回的屏列表里，`地址管理` 屏 5 只有 2 个节点、0 条文案，看不出是空框；写进 plan 就换来一份空规格表和一个必然的「这屏是空的吗」的来回。

## Decision

1. **顶栏候选改为在全部盒子里找**（[spec.mjs](../../../lib/spec.mjs) `detectScreenChrome`）：`depth > 0`、`x <= 4`、宽 ≥ 屏宽 90%、且 `y <= 4 && y + h <= 屏宽 × 0.32` 的盒子进候选；每条仍要满足原先的内容条件（带时钟或命名线索、文案 ≤ 2 条）。状态栏与导航栏分开画的设计稿走第二块分支（紧贴 `topBottom` 下沿、文案 ≤ 1 条、不含「搜索/请输入」）。候选按 `y` 升序、高度降序排，取到的最外层就是整条顶栏；循环不再 `break`，因为两块都要。
2. **顶栏注释固定在根节点下一行**（`specMarkdown`）：`walk` 之前记下 `treeStart`，`walk` 之后 `L.splice(treeStart + 1, 0, …)`。之前注释跟着它所在框的缩进输出（塞在卡片里就有八层缩进），读起来像那个卡片的内容。
3. **返回 `unplanned`**（[build.mjs](../../../lib/build.mjs)）：`[{ index, title, nodes, empty? }]`，写进 `report.md` 一条「**未纳入 plan 的屏**：…——空屏可以忽略，其余要么补进 plan，要么先问用户」。同时 `screens` 的屏列表对 `nodes <= 3` 加 `empty: true`，让选择发生在 plan 之前。
4. **零差异屏对不进 `variants-diff.md`**（[variants.mjs](../../../lib/variants.mjs)）：`buildVariantsDiff` 返回 `{ pairs, identical, markdown }`，`pairs` 只留真正有差异的，`identical` 写进 `report.md` 一句「结构完全一致、只有标题不同的屏对：#0（收货地址） = #7（地址管理）——同一套布局，按一个页面实现」。`markdown` 为空时不写文件（旧的同名文件会被删掉）。
5. **大段留白加标注**（`specMarkdown`）：`↑gap >= 240` 时追加 `[大段留白：多为固定高度稿的摆放，用 flex 撑开别写死]`。
6. **画布行只说画布**（[report.mjs](../../../lib/report.mjs)）：写「画布 9382×3254 设计像素（整张设计图，含 10 屏），缩放比 @2x」，删掉「逻辑宽」。
7. **按画布累计 plan**（[store.mjs](../../../lib/store.mjs) `PLANS_FILE = 'plans.json'`）：[build.mjs](../../../lib/build.mjs) 以 `meta.imageId` 为键合并写入（`PLAN_FILE` 继续写，保持旧路径可用）；[index.js](../../../index.js) 的 `closeout` 读 `plans.json`，只有一张画布时保持原来的扁平形状（多一个 `title`），多张时返回 `{ canvasCount, canvases: [{ title, mode, pages, keep, drop }], next }`。
8. **技能与 README 同步**：SKILL.md 的 `screens` 说明加 `empty`、产物表加两条提示、布局一节加「大段留白用 flex 撑开」、收尾一节写清多画布 `closeout`；README 的工具表与「已知边界」写明多画布收尾与「页面 + 盖在上面的确认框」这种同帧混排稿的边界。

## Alternatives considered

### 顶栏只认根节点的直接子节点，靠坐标补一条

改前就是这么做的（`rootBox.kids` + `x <= 4`）。补坐标救不了「被分组塞进卡片」——它根本不在 `rootBox.kids` 里。全量扫 `boxes` 是唯一能覆盖分组任意深度的办法，代价是每个盒子都要过一遍坐标判断（51~200 节点的量级，可忽略）。

### 用「顶栏必须在 depth 1」限制候选

`我的订单` 的顶栏在 `depth 2`（卡片 `box-4` 里），这条限制会把它和真实设计里「卡片内贴顶的头部区块」一起排除，等于把 bug 换个形态留着。

### 零差异屏对直接不配对

少一次配对，`地址管理` 屏 0/7 就各自成为「一个页面」，用户会得到两份重复实现。降级成 `report.md` 一句话比不配对好，也比在 `variants-diff.md` 里留一节空表好。

### `unplanned` 只报数量

「缺了 1 屏」不足以让模型判断该补还是该忽略。带上 `index`、`title`、`nodes`、`empty` 才能让它自己决定，也才能让用户在报告里核对。

### `plans.json` 用数组按时间追加

同一张画布重跑（改 plan 后重编）会追加第二条，收尾清单里同一张图出现两次，用户无法判断哪条有效。以 `imageId` 为键覆盖是幂等的。

## Consequences

- **收益**（五个真实链接重跑）：`我的订单` 屏 1–4 的 `9:41` 计数从 4 变 0、`title:"订单详情"`、首个内容块带 `↑nav:0`；`地址管理` 的 `variants-diff.md` 只剩 `3↔4` 一组、`report.md` 多出 identical 与 unplanned 两条；`首页` 的 `unplanned` 明确列出被排除的密码键盘屏（53 节点）；`closeout` 返回 `canvasCount: 5` 与五个画布的 pages。
- **代价**：`detectScreenChrome` 从「看根的直接子节点」变成「全量扫盒子」，每屏多一次 O(n) 遍历；`↑gap >= 240` 的阈值是按这批真实数据定的（p90 = 38，240 与它差一个数量级），别的项目若习惯用大间距排版，这一段会误标。
- **验证**：`node --check` 全部通过；`/tmp/lanhu-golden/verify-091.mjs` 与 `verify-092.mjs` 改动前后均 `ALL PASS`；五个真实链接（结果页、发票、地址、订单、首页）全部重新编译，产物逐项核对；`closeout` 多画布路径用 `DSH_CWD=/tmp/lanhu-proj` 实测返回五个画布。
- **未验证**：`地址管理` 屏 6（标题「账号安全」，内容是地址详情 + 删除确认弹窗）没被识别成弹层，这是设计稿本身把页面和弹层画在同一帧里，插件按一个页面输出，拆不拆成两个状态仍需模型读文案后问用户；`我的订单` 顶栏下那张 750×529 的渐变底图从 `y=60` 起画，折叠顶栏后与设计稿（渐变延伸到状态栏下）差 60px，未处理。
