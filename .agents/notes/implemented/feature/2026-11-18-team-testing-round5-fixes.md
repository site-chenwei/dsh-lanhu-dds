# Agent Note: 团队测试第五轮——校验时序、处方误指与产物一致性收尾

Status: implemented

## Problem

第五轮回归代理（19 项清单）+ 出新眼睛代理（按 SKILL 真写代码）在第四轮修复后的产物上又抓到 5 类残留缺陷，全部是「修复只做了一半」的性质：

1. **校验时序（P1）**：`lib/build.mjs` 的 `prevalidatePlan` 只查 `file` 与非空数组，屏号元素类型与 `keep`/`drop` 形状留在联网后才跑的 `normalizePlan` 里。配一份过期 Cookie 时 `screens:[true]` 报成 `HTTP 418 …permission to access this project!`（579ms，被误诊成 Cookie 问题），真实 Cookie 下也要白跑 1.6–1.8s 才报 plan 错——与第四轮「参数校验全部前置」的决策自相矛盾。
2. **处方误指（P1）**：`lib/spec.mjs` 的负偏移提示一律教「父容器记得 `overflow: hidden` 裁剪」。实际触发它的多数是**宽度超过父容器的通栏层**（gold 屏 3/5 的 `box-46` 吸底栏 750 宽、父容器只有 646 宽，`rel(-52,797)`；orders 的导航底图 `box-83`），照处方裁剪会把吸底栏右侧 104px 切掉——比不提示更糟。
3. **产物写法不一致（P3）**：`tokens.css` 里出现 `rgba(255,255,255,1.000000)`，而同一份规格表的树行写 `bg:rgba(255,255,255,1)`（树行走 `cleanCssColorNoise`）。同一颜色两种写法，模型对色时会当成两个色值。
4. **字体栈重复（P3）**：`familyStack` 给 PingFang/SF 系列额外追加了一次 `"Microsoft YaHei"`，而栈尾本来就有，输出 `"PingFang SC", "Microsoft YaHei", "Microsoft YaHei", system-ui …`。
5. **坐标归一文案编数字（P3，lead 自查发现）**：`unit:css` 且项目没给基准时 `designWidth` 为 0，归一行写成「本屏实测宽 750px，是项目 **0** 基准的 2 倍，本表所有数值已 ÷2，可直接写进代码」。

另外「出新眼睛」代理真按 SKILL 写代码，又报出 5 条产物本身的误导（这些不是它写错，是规格表把它带歪）：

6. **P0 安全区占位缩进把兄弟洗成子节点**：`screen-9.spec.md` 里安全区占位按 `'  '.repeat(Math.min(b.depth, 1))` 印在 indent 1，而它的兄弟在 indent 3、紧随其后的真实节点 `box-46`（658×104 密码框）在 indent 2——按 SKILL「忽略安全区占位」删掉这一行，密码框会被连带当成占位的一部分删掉；按 `rel` 累加则落到屏外 244px。
7. **P1 行高提示自带的例子落在不需要修正的节点上**：`screen-0.spec.md` 里「父行 ↑gap:28、line-height 36、图层高 30 → margin 取 22」取自 `text-29`，而它的父行高度是兄弟 `text-28` 撑起来的（本来就居中），照例子改 margin 会把它顶歪。
8. **P1 `jc:space-between` 把底部安全区摊成间距**：`invoice` 屏 1/2 的弹层容器子块合计 552/653、容器 620/721，空出的 68 正是安全区；按 `space-between` 复现会让中间块下移 34、底部按钮贴到屏底 68。
9. **P1 容器尺寸提示与「卡片写死 height」互相矛盾**：gold 屏 0 的 6 张卡必须写死 `@h`（513/552）才像素级还原，但提示只说「内容撑开的容器按子节点还原，不要照抄 height」，没有给判据，照办每卡矮 25。
10. **P2 容器尺寸判据把固定底内距当定高（本轮新提示自己踩的）**：改成「差 >4px 就写死 height」后，gold 屏 0 的四张卡（差 26 = 2px 边框 + 24px 底内距，且两张卡的高差 39 正好是标题行盒高）被推进「定高摆放」分支——写死 513/552 后标题换两行就被裁。
11. **P2 键盘容器内「安全区上方 44px」无任何表达**：`screen-9` 末行底 1516、安全区占位 1560..1624，中间 44px 既不在占位的 `↑gap` 里（占位分支提前 return），也不在容器 `pad` 里（DDS 不导出），照 SKILL 直接写 `safe-area-inset-bottom: 64` 会让键位整块下移 44。
12. **P3 行高例子的标签写死 `↑gap`**：首块内容的父行在树里印的是 `↑nav:28`，例子却说「父行 ↑gap:28」，照它去树里搜会搜到另一行。
13. **P3 tokens/report 颜色统计混进被折叠的壳层**：`tokens.css` 里 `rgba(0,0,0,0.9)×7`、`rgba(255,255,255,0.6)×7` 全来自导航壳；address 的 `--color-brand-2: rgba(0,0,0,1)×24`（每屏 4 个状态栏节点 ×6 屏）在 spec 里 0 次出现却排到 report 第 2——照它写会拿壳层纯黑当正文色。

15. **P1 容器内距的处方方向错**：第二轮改成的「差额 4–48px 就写 `padding-bottom`」只在「内距全在下」时成立——真实夹具 169 个 4–48 容器里只有 20 个纯底部（gold 18、address 2），144 个上下都有、5 个只有上部；orders 38/38、invoice 26/26 全部非纯底部。照它写：内容整块上移 12–24px（result0 上移 20、invoice0 上移 24、gold4 上移 12）。
16. **P2 底部安全区容器同时被两条提示指向相反动作**：invoice s1/s2、gold s4/s6 的 `box-1` 既被算进「>48 写死 height」，又被底部内缩提示要求 `padding-bottom: 68px`；只照前者写 `height` + 树里 `jc:space-between`，68 会被摊成两个 34px（`box-6` 下移 34、`box-17` 下移 68）。
17. **P2 差额把容器自己的上下边框算进去了**：`span` 只累加子块高 + gap，`diff = h − span` 因此含 2–3px 边框；35 个容器中招（gold s0 六张卡 26 实为 24、gold s7/s8 的 9 实为 6、address/orders 的 40/24 含 2–3px）。照写 padding 会多 2–3px，定高时底部被压。
18. **P3 行高例子先取整再喊「别取整」**：`Math.round(lhPx - h)` 与 `Math.round(val - d)` 让 13 条例子里 7 条印整数（orders s1/s2 印 30），同一句后面却写着「算出 30.4 就写 30.4」。
19. **P3 行高公式只提 `↑gap`，例子用的是 `↑nav`**：gold s2 例子是 `↑nav:28`，公式句没有 `↑nav` 字样，模型可能漏掉首块内容相对导航底的补偿。

20. **P1 边框被写成四边描边**（新眼睛出码 drill）：`border:1px solid rgba(230,230,230,1)` 记在每张卡上，实际裁图只有卡片之间的一条 1px 分隔线（address 屏 1 的 x=0/749 全白，363/551/739/927 才有色）。照写多出 6 条整线，分隔线还叠成 2px 双线。
21. **P1 多行文案的差额被两头漏掉**：`text-18` 图层高 84、两行行盒合计 78.4（+5.6），既不在「单行文字行高」提示里（拿单行行盒去减得 −44.8 被筛），也不在「文字盒高度」提示里（超过 40 被筛），照写文案块矮 5.6、下面整屏上移。
22. **P1 容器名单只点名前 4 个却写「等 N 个」**：照只写点名的 4 个，第 3/4 张卡塌成 150（矮 38）。
23. **P3 区间与分档都用了取整值**：文字盒高度印「7–10px」实为 6.6/8.4/9.6；行高分档印「+6px×16」实为 5.6×14 + 6.4×2——和第 18 条同源，统计口径没跟「别取整」对齐。
24. **P3 SKILL 的边框配方漏了盒模型**：教「行只写 `border-bottom`」但没提 `@h` 含原描边，改完每行矮 1px。
25. **P3 多色图标不给主色与状态**：4 张卡的图标同形不同色（选中态），清单只标「多色」，照同形节点写灰色占位 → 4 张卡一模一样、选中态丢失，而 rect/尺寸比对查不出来。

14. **P3 `--color-text-primary` 变量名骗人**：它其实是 compile.mjs 给「DDS 没给文字色」的节点准备的回退色，取的是出现次数最多的文字色（价格红 ×60 胜过正文 #333 ×32），名字却长得像项目主文字色。

## Decision

- **形状校验整段挪进 `prevalidatePlan`**：屏号元素（数字或纯数字字符串）与 `keep`/`drop`（字符串数组）的检查跟着 `file` 一起在 `buildDesign` 开头跑（`if (!list) prevalidatePlan(rawPlan)` 位于任何 `fetch` 之前）。`normalizePlan` 只保留需要 `totalScreens` 的范围/重复校验与字符串化，`list()` 退化为纯粹的 map/filter。判据：假 Cookie + `screens:[true]` 必须在 1–2ms 内报 plan 错，且错误里不出现 HTTP 状态码。
- **负偏移提示按两种情形分开给处方**：①装饰圆/悬浮角标这类小贴片 → 绝对定位，父容器按需 `overflow: hidden`；②宽度超过父容器的通栏层（横幅、吸底栏、通栏图）→ 同样绝对定位或提到父级渲染，但**明确写「不要裁剪」**并解释 `overflow: hidden` 会切掉伸出去的那一截。两种都别当流内子节点排。
- **tokens 颜色统一走 `cleanCssColorNoise`**：`collectTokens` 提取的每个色字面量先规整再加计数（`render-html.mjs` 从 `spec.mjs` 引该函数，spec 只依赖 util，无循环）。附带收益：`1.000000` 与 `1` 归并成同一个 key，频次不再被拆散。
- **删掉 `familyStack` 里重复的 win 追加**：栈尾已有 `"Microsoft YaHei"`，PingFang 分支的追加纯冗余。
- **坐标归一行按来源说人话**：`unit !== 'css' && designWidth > 0` 才写「项目基准 750px」，否则写「切图倍率 @2x」。**不**把 `designWidth` 塞进 css 模式的 meta——css 模式的除数来自切图倍率而不是项目基准，写「按 750 基准」自相矛盾。
- **out 名清洗要在返回体里说清**：目录名被清洗或截断时补一条 warning（`out 名里有不能做目录名的字符或过长，实际目录是 <basename>（原始值：…）`），否则用户按 out 找目录找不到。
- **安全区占位按自己的 `depth` 缩进**：占位行是「替身」，缩进必须和被替身节点一致，否则浅一级就变成后面兄弟的父节点。这条是第五轮唯一的 P0，成因就是当初为了「让它在根级好看」写了 `Math.min(depth, 1)`。
- **行高例子只在「这行高度是它撑起的」时给**：候选样本必须是自己父行里最高的可见子块（`b.h >= max(kid.h) - 1`），否则行高由更高的兄弟决定，把差额算到行距上是错的；没有合格样本就只留规则、不举例（`lhSamples` 为空时句子自动收尾）。
- **新增「底部内缩提示」**：容器 `jc:space-between` 且「容器高 − 可见子块高之和」与某个底部安全区占位的高度、底边同时吻合（±4px）时，判定这点空隙是安全区内缩，让模型写 `padding-bottom: N`（或 `env(safe-area-inset-bottom)`）而不是摊成间距。判据要求两重吻合，避免把真间隙误判成安全区。
- **容器尺寸提示补判据**：先算子块 + 间距之和与 `@h` 的差——≤4px 按内容还原，>4px 认定为定高摆放、写 `height`（补一句「往里加内容会溢出，改 `min-height` 自己排」）。把原来「一律不要照抄 height」的口径改成可判定，卡片与弹层都能落到明确分支。
- **容器内距改按 rect 反推，不再按差额猜档位**：`上内距 = 首子块顶 − 盒顶 − 上边框`、`下内距 = 盒底 − 末子块底 − 下边框`（边框宽度取 `css.borderTop/borderBottom/border` 的第一个 px 值，已扣掉，提示里说明）；按「上下各 X / 上 X、下 Y / 只在下 Y / 只在上 X」给值，让模型直接写 `padding-top`/`padding-bottom`，并说明别用 `justify-content` 摊（内容一增减就摊歪）——差额÷2 只对上下对称成立，方向给错会把内容整块推下去。内距约 0 的容器按子节点还原、不写死 `height`；上下都约 0 却空出一大块的才是定高摆放。这样底部安全区容器自然得到「只在下 68」，与底部内缩提示同向，不再一屏两套处方。
- **两条提示分层说清**：容器内距是「容器 vs 直接子块」，行高提示是「文字盒内部行盒 vs 图层高」，提示里明写「内距照这里写、行盒高度照行高提示写」，消掉 gold s4 按钮（12/12 vs ±2.5）这类看起来打架的数。
- **边框单边化提示 + 盒模型**：图例与 SKILL 都改成「`border:` 是 DDS 属性、不等于四边有线，相邻卡片的分隔线会被记成两张卡的 border；按 `screen-N.png` 确认哪一边，只写单边时加 `box-sizing: border-box`（或把高度补回 1px）」。
- **多行文案按「行数 × 行盒」比**：`lines = max(1, round(h / 行盒))`，单行与多行走同一套差公式，`text-18` 这类（84 vs 78.4）不再被两头漏掉。
- **统计数字一律不取整**：文字盒高度区间、行高分档都按 1 位小数给（6.6–9.6px、+5.6px×14、+6.4px×2），与「30.4 就写 30.4」同口径；单值区间不再印「12–12px」。
- **容器名单说明只列前 4**：补「本屏共 N 个容器有内距，这里只列前 4 个；没列到的按同样办法从树行与 `rel()` 反推，别只写点名的」。
- **多色图标**：图标清单加「多色常带选中/未选中两套，按裁图确认主色与状态，别用同形灰色占位（尺寸比对查不出来）」。
- **行高例子不取整**：`margin 取 30.4` 这种直接印小数，和同句「别取整」一致；公式句补上 `↑nav`（首块内容的父行在树里标的是 `↑nav`）。
- **安全区占位行补 `↑gap`**：占位不参与排版，但它到上一个兄弟的距离是真实留白（键盘区 44px 这类），不印出来就会被当成安全区的一部分。
- **行高例子的标签跟树走**：父行是第一块内容时树里印 `↑nav`（值取 `par.y − chrome.topBottom`），否则 `↑gap`（取 `par.gap.px`）。
- **tokens 排除壳层色**：`collectTokens` 用 `detectScreenChrome` 的 `skipNodeSet` 过滤状态栏/导航栏/底部安全区节点，色板与 `--font-*`/`--color-brand-N` 只统计业务节点；壳层文字色单独留一份兜底，仅当业务文字色为空时才拿来填 `--color-text-primary`（compile 会把缺色文本指向该变量，不能让它没值）。
- **`--color-text-primary` 加派生注释**：tokens.css 里在该变量前写清「缺色文本引用它：取本设计稿出现次数最多的文字色，不代表项目主文字色」——变量名不能改（compile.mjs 用它做缺失色回退），只能靠注释纠偏。
- **variants 独有段落标题写出配对屏**：`### 只在 Screen 2 有、Screen 3 没有`。原来只写「仅在 Screen 2」，新眼睛把它读成「与上一节那两屏比」，据此报了一条并不存在的假缺陷。

## Alternatives considered

- **把 `designWidth` 一律写进 meta，让归一行总能引用项目基准**：否。`unit:css` 的 `div` 是切图倍率，与 `designWidth` 无因果关系；两者不等时（css 模式传 750）会输出「按 750 基准 ÷2」这种自相矛盾的话。
- **负偏移只在「宽度超过父容器」时才提示、装饰贴片不提示**：否。装饰圆超出父边界同样会让照抄 `rel` 的模型把上方内容顶开，两种情形都需要提示，只是处方不同。
- **`tokens.css` 保留 DDS 原始精度（1.000000）以「如实反映设计稿」**：否。规格表树行早已规整到 3 位小数，两份产物必须同写法；原始精度对写代码没有任何价值。
- **把形状校验留在 `normalizePlan`、只在 `buildDesign` 里提前调一次 `normalizePlan(plan, Infinity)` 做预检**：否。为预检造一个假的 `totalScreens`，范围校验会在错误时机报「共 Infinity 屏」，比现在更难维护。
- **variants 独有块里补一句「同文案在另一屏也有」**：写过又撤回。真实夹具 0 命中（无法验证措辞），而且「别当新增」是强断言，同文案撞车时会把真新增控件说成旧的；改成把配对屏写进小标题，成本更低、不会误伤。
- **安全区占位改成不打印、只留一行壳层规则**：否。占位的 `@(x,y w×h)` 是吸底栏做 `safe-area-inset-bottom` 适配的唯一尺寸依据，删掉就得让模型猜高度。

## Consequences

- **代价**：`prevalidatePlan` 多遍历一遍屏号（纳秒级）；`collectTokens` 每色多一次正则替换（五画布全量 <5ms）。
